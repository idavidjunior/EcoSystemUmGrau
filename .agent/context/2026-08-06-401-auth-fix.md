# Bug: HTTP 401 Unauthorized on OpenCode Serve

## Sintoma
Todas as requests HTTP para opencode serve retornavam 401 Unauthorized.
O bridge Jarvis nao conseguia criar sessoes, mandar mensagens ou fazer
qualquer coisa com o LLM.

## Causa Raiz
1. O serve (PID 4724) foi iniciado com OPENCODE_SERVER_PASSWORD=521cf1f4-...
   (variavel de ambiente do Windows, do registro HKCU).
2. O arquivo .env foi atualizado para edbe7432-2bab-454c-b6d5-dd23f9380bba
   mas o serve nunca foi reiniciado.
3. O bridge leo o .env via load_dotenv(override=True) e usa a nova senha,
   mas o serve roda com a senha antiga.
4. Nenhuma das duas senhas funcionava contra o serve rodando.

## Fix
- Atualizada variavel de ambiente do Windows (HKCU\Environment) para bater
  com o .env: OPENCODE_SERVER_PASSWORD=edbe7432-...
- Morto o serve antigo (PID 4724)
- Iniciado novo serve (PID 4216) com a senha correta
- Verificado: POST /session retorna 200 com auth

## Learning
Sempre manter o Windows env var sincronizado com o .env.

un_serve.py agora carrega .env explicitamente e passa env ao subprocess.
_ensure_serve() em jarvis_bridge.py agora passa env={**os.environ}
explicitamente para garantir que futuros restarts de serve herdem a senha certa.

## Arquivos modificados
- scripts/run_serve.py — adicionado load_dotenv + env explicito
- scripts/jarvis_bridge.py — adicionado env={**os.environ} em _ensure_serve e _ensure_serve_global
- scripts/JARVIS_SYSTEM.md — atualizada senha de referencia
