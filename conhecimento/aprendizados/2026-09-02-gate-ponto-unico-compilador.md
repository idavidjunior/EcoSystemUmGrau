contexto: O usuário perguntou se a ordem de commit/push do ecossistema realmente parte de um único lugar (o gate persistencia.ps1) ou se existem vários pontos emitindo ordens. Ao auditar, encontrei desvios reais do gate e precisei decidir como tratá-los sem quebrar fluxos legítimos.
decisao: (1) Corpus no núcleo do EcoSystemUmGrau: scripts/ecosystem.ps1 nas funções repair (linhas 352-353) e learn (linhas 408-410) faziam `git add`/`git commit`/`git push` direto, fora do gate. Isso gerou um commit real fora do gate hoje às 06:43 (`[ecosystem learn] 2026-09-02 06:43`, hash 3173e01eb). A correção aplicada: as duas funções agora delegam ao gate via `& powershell -ExecutionPolicy Bypass -File "$ecoDir\scripts\persistencia.ps1" run-sync -Repo eco -Label "ecosystem repair|learn" -Push`. (2) Projetos/compiladorAPK/scripts/apk-compiler-ui.ps1 possui ~17 pontos de `git add`/`commit`/`push` (incluindo `git push --force`) — porém o diagnóstico mostrou que todos operam em diretórios temporários de build efêmeros (`$env:TEMP\apk-*`/`apk-build-*`, linhas 730/756/2855), onde o script remove o `.git`, refaz `git init` do zero e dá push forçado para um repositório de artefatos APK (`apk-builds`) criado via API GitHub só para disparar GitHub Actions. NÃO é persistência de conhecimento nem repositório que o gate varre. A decisão do usuário: manter o robô como está (não delegar ao gate), porque forçar a delegação quebraria a geração de APK; registrar como exceção de CI de build. O robô já está dentro da casa (Projetos/) e já respeita o gate quando guarda conhecimento próprio; o modo de montar app é entrega de artefato, fora do escopo do gate de conhecimento.
impacto: A regra do ponto único de persistência fica restaurada no núcleo do ecossistema: toda chamada a git add/commit/push que toca conhecimento do ecossistema passa pelo gate persistencia.ps1. O fluxo de build do compiladorAPK continua funcionando sem mudanças (caso correto de exceção). Removido o risco de commits paralelos fora do gate vindos do learn/repair automáticos do vigilante.
